# 공식 데이터 자동 갱신

## 확인한 공식 자료 (2026-11-25)

- 데이터: [한국부동산원 청약홈 분양정보 조회 서비스](https://www.data.go.kr/data/15098547/openapi.do), 식별자 15098547.
- 포털 표시: 무료, 이용허락범위 제한 없음. 공개 API 데이터의 상업적 활용 근거로 삼는다. 첨부 PDF, 사진, 로고, 다른 사이트 콘텐츠의 재배포 권리까지 확인된 것은 아니다.
- 개발계정은 자동승인, 운영계정은 심의승인으로 안내된다. 출시 전 운영계정 신청과 승인된 트래픽 범위를 확인한다.
- [공식 기술문서](https://www.reb.or.kr/reb/na/ntt/selectNttInfo.do?mi=10251&bbsId=1268&nttSn=79889), [Swagger 명세](https://infuser.odcloud.kr/api/stages/37000/api-docs).

## 구현 범위

Python 표준 라이브러리만 사용한다. APT, 무순위·잔여세대, 오피스텔·기타, 공공지원민간임대, 임의공급의 상세/주택형 API 10개를 사용한다. 공고일로 수집 범위를 자르지 않고 모든 페이지를 읽은 뒤 한국시간 기준 마감된 공고를 제외한다. 접수일 미확인 공고는 삭제하지 않는다.

공고번호/주택관리번호를 함께 사용한다. 5개 목록과 활성 공고의 주택형 수집이 모두 성공한 뒤에만 listings.json을 원자적으로 교체한다. 일부 목록 실패·페이지 누락·중복·잘못된 날짜가 있으면 기존 파일을 보존한다. 상태는 sync-status.json에 따로 기록한다. 전체 목록이 비었을 때는 이상 응답으로 처리한다. 정상적으로 조회된 과거 공고는 있지만 현재 활성 공고가 없는 경우 0건을 허용한다.

API의 주택형별 공급금액은 최고금액이다. 표시된 범위는 주택형별 최고금액 사이의 범위이며 개별 세대의 최저 분양가가 아니다. API에 없는 자격 요건은 추정하지 않는다. 별도 검토 데이터가 있고 현재 공식 PDF 해시와 일치하는 공고에만 항목별 근거를 연결한다. [자격 근거 검토](eligibility.md)를 참고한다. 입력 조건 부합은 최종 자격 충족을 뜻하지 않는다.

## 인증키 등록 및 가동

1. 공공데이터포털에서 위 서비스의 활용신청을 한다.
2. GitHub 저장소 Settings → Secrets and variables → Actions → New repository secret에 `APPLYHOME_SERVICE_KEY`를 등록한다. 일반 인증키(Decoding)를 권장한다. 키를 코드·공개 파일·채팅에 붙이지 않는다.
3. 변경 파일을 main에 반영한다. Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택한다.
4. Actions → Sync official Applyhome data → Run workflow로 첫 실행을 한다.
5. 실행 성공, data/sync-status.json의 status=ok, 웹의 마지막 갱신 시간을 확인한다. 실패하면 기존 공고가 유지되는지도 확인한다.

기본 실행 예약은 매일 한국시간 09:37, 15:37이다. GitHub 일정 실행은 지연되거나 누락될 수 있다. 기본 브랜치에 워크플로가 있어야 하며, 공개 저장소의 장기 미활동 시 일정이 비활성화될 수 있다. 출시 후 정시성이 중요해지면 별도 스케줄러와 외부 감시를 도입한다.

워크플로는 갱신된 데이터/상태를 main에 커밋한 뒤 Pages를 명시적으로 배포한다. bot 커밋만으로는 Pages 갱신을 보장할 수 없기 때문이다. 갱신 실패 때도 이전 공고와 실패 상태를 배포하고 실행 결과는 실패로 남긴다. main 브랜치 보호 규칙이 bot 직접 커밋을 금지한다면 데이터 전용 브랜치 등 배포 구조 변경이 필요하다. 다른 호스팅 서비스를 사용한다면 해당 배포 연결도 설정해야 한다.

## Windows에서 실행 및 검증

인증키를 환경변수 `APPLYHOME_SERVICE_KEY`로 설정한 터미널에서:

```powershell
python -m unittest discover -s tests -v
node --test tests/ui-status.test.cjs
python scripts/sync_applyhome.py
python -m http.server 8000
```

브라우저에서 http://localhost:8000 을 연다. 앱은 공개 JSON만 읽으며 인증키는 브라우저로 전달하지 않는다. 갱신 상태 조회 실패, 수집 실패, 미설정, 30시간 이상 경과, 데이터와 상태 시간 불일치를 구별한다. 인증키가 없는 상태에서는 성공 시각을 만들지 않는다.

## 현재 가동 상태

코드와 실행 설정을 준비한 단계다. 실제 인증키로 API 응답을 받아 저장하는 통합 검증과 GitHub 예약 실행/배포 확인은 인증키 등록 및 저장소 반영 후 수행해야 한다. 기존 38건 데이터는 실시간 API로 검증된 최신 데이터로 간주하지 않는다.
